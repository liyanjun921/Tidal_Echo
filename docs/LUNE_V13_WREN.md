# Luné V0.13 · WrenWen 自主空间

依据用户 fork 的 [WrenWen](https://github.com/liyanjun921/WrenWen)，固定阅读版本 `b987ae0ae9154f782920062358ea693e8388d6a0`。该仓库只有架构文档，作者的生产代码和人格正文未公开。本版是 Luné 宿主的独立实现，不声称安装或运行 WrenWen 私有程序。本次保存开发分支，未正式部署。

入口：侧边栏 **自主空间 · Room**。沿用灰白蓝水光与液态玻璃，提供“此刻 / 提醒 / 足迹 / 节奏”四页，四个空间分别保存：GPT、Claude、群聊 GPT、群聊 Claude。它与现有聊天、待办、共读、日记、Duet 和 Ombre 工作台相连，不新增记忆引擎选择。

## 实际实现与读写闭环

| 机制 | 写口 | 读口与实际行为 |
| --- | --- | --- |
| 九维驱动 | 模型在真实有效回合中调用 `lune_room thought`，须提供本房间消息编号和逐字引文；用户可在节奏页修改九维底色 | 此刻页显示公开投影；状态和抽象意图进入本房间后续聊天与唤醒上下文。初始底色全部为零，不移植别人的人格数值；不推断用户情绪 |
| 驱动动力学 | 公开来源信号增加对应偏移；`satisfy` 将对应维度偏移归零 | 相对底色的偏移以 8 小时半衰期缓动；固定次序裁决同分；疲劳 ≥0.7 直接休息，其他维度不与疲劳竞争；表达门槛 0.35 |
| 念头池 | 引文逐字回查，拒绝跨房间、未来消息、已报错或日期未知材料；同信号 5 分钟内重试不算新触达 | 闪念以 6 小时半衰期衰减，低于 0.02 不再呈现；第 3 次触达成为执念；执念提供 0.15 意图加成；8 个不同真实回合确认满足后退场；每空间最多 200 条，优先淘汰已退场、弱、旧信号 |
| 私有投影 | 未知或缺失 visibility 一律私有；已有私有条目不能经重试改成公开 | 用户接口不返回私有正文、数量、满足记录或由它产生的公开驱动。模型 `read` 只读自身空间；自动上下文仅包含公开念头。私有状态没有写入 Latent/Ombre 公共召回池 |
| 空闲唤醒 | 用户显式开启；每条新的人类消息重置服务端倒计时；回合结束重新起表 | 默认关闭。开启后默认 120–240 分钟、每空间每日最多 5 个后台回合，可调整至最多 10；默认上海时区 23:00–08:00 安静。驱动不加速唤醒，不按用户情绪改频率 |
| 唤醒出口 | 同一模型连接生成 JSON 契约：say / note / pass | say 原子写入原房间聊天，再 SSE/推送；note 只留 Room 手记；pass 留账但无正文。JSON 外壳不进聊天。没有合适内容不补造话语 |
| 上下文 | 复用现有 `build_messages` 的人格、原文历史、Latent、Ombre 与本空间材料 | 自动带入最多 3 条公开念头、8 条已有未完成待办及结构化时间；有来源标识、长度限制与观测记录。后台生成无动作工具、不插入伪造的人类消息；Claude 订阅走现有临时、无工具的官方 CLI 路线 |
| 私聊追问 | 有效回合的 `lune_room followup`，仅在用户希望稍后续接且已开启唤醒时可排；1–1440 分钟 | 每空间只留一个待触发追问，任何新的人类消息取消。群聊拒绝追问；后台唤醒没有排点工具，不能不断自续。重复工具请求复用原预约 |
| 原话提醒 say | 用户在提醒页写好正文、时间与是否每 24 小时重复 | 到时绕过模型，逐字落入原聊天；不占模型回合上限。不支持已经退役的 note 软提醒档 |
| 唤醒提醒 remind | 用户明确预约同一提醒表中的另一种投递方式 | 到时使用对应房间模型、人格与记忆；可以发言、留手记或 PASS，不保证逐字照发。原话必须发生时应选 say |
| 足迹与观测 | 所有后台回合持久记录状态、正文、真实返回 usage、聊天消息编号和错误；装配记录实际字数/数量 | 足迹页回查，显示当日剩余后台回合和安静状态。供应商没给用量就不推算费用、缓存命中率或 token 数 |

驱动是状态模型，不是模型具有真实情绪的证明。半衰期只应用于新增的驱动/闪念，不修改 Latent 的无时间衰减策略或 Ombre 自身权重。没有直接移植 WrenWen 文档中为另一组作息、模型和语料校准的峰时、记忆门槛 75、缓存参数或私人文案。

## 运行与恢复

随原 relay 启动，15 秒检查一次到期事项。生成前要求本房间没有待回复回合，且最近聊天已空闲 30 秒；生成中约 0.2 秒检查聊天活动；提交时在写事务内再次校验游标、回复任务、设置版本和预约状态。新消息、取消预约或修改设置使旧草稿让位。宿主取消不等于供应商承诺撤销远程用量。

数据库先原子提交“聊天回复 + 后台足迹 + 预约状态”，随后广播/推送。通知失败不重跑模型，重新读取聊天可恢复已保存正文。幂等编号、到期次数与事务内唯一检查防止重复投递；这不是对外部通知端到端恰好一次的保证。重启时未确认任务标记中断，不盲目重放；失败预约可取消后明确重新创建。每 24 小时重复会跳过停机错过的次数，只投递当前一次，不补发一串旧消息。

明确设置的提醒独立于自主唤醒开关及安静时段，但同样等待聊天空闲；remind 和追问/唤醒共用每日后台回合上限，say 无模型调用。超出上限的预约留待下一日检查；手动请求会明确报告上限。服务离线、持续聊天或额度用尽时不能保证准点，不能替代系统闹钟。旧聊天首次进入新模块时从当前观察时刻起表，不补跑历史唤醒。

所有状态随现有私人 SQLite 保存，新增 `lune_wren_*` 表。完整备份须包含服务数据库与原有私人配置/档案/附件；旧聊天 JSON、Latent ZIP、Ombre ZIP 不含完整 Room 状态。私有可见性是应用规则，服务器管理员仍可读取数据库，不是端到端加密。服务端模型密钥不进入新增前端文件。

## 验证

108 项 Python 回归通过，其中新增 13 项针对原话、权限、私有投影、半衰期、念头生命周期/上限、时区/版本、持久锚点、追问取消、疲劳、预算、抢占、原话绕过模型、无效输出和重复投递的边界测试。最后的预算观测调整后重新通过全部 13 项 Room 测试；JS 语法、Python 编译与 diff 检查通过。

真实本地 HTTP 联调使用完整 supervisor、relay SQLite、真实固定版 Latent / Ombre / Folio 和本地 BGE，模型与官方 CLI 由合成供应商/协议进程承担。新增链路验证：普通聊天的模型工具写入有出处念头 → 本空间上下文装配 → 无工具唤醒 → 原时间线持久回复与真实返回 usage → 重复请求不再调用 → 全进程重启后念头、账、设置与倒计时保留。原有16基础工具、You/Them、Folio精修/导入/锁信、Duet/常驻CLI等回归亦通过。

浏览器检查未连接时禁用操作，并用上述合成 HTTP 结果的只读快照核对驱动、原话来源、足迹/用量和节奏设置，发现并修复 HTTP 预览的 `crypto.randomUUID` 初始化兼容性；改用 `crypto.getRandomValues` 生成幂等编号。该浏览器环境无法直接运行当前 Python 环境，未声称浏览器直连后端、真实模型自然主动性或 iPhone/Windows 真机已经验收。正式账号、实际额度、通知分寸和长期召回质量仍需对应环境验证。
