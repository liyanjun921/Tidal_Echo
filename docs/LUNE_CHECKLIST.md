# Luné 定时清单

用户 fork `liyanjun921/timed-checklist` 的检查版本为 `4a0500b184ecf6b1d5e214f47878e102ff526ef1`。其作者 nonchaiovo 的许可证仅允许个人非商业使用，要求署名，并禁止公开再分发源码和衍生作品。Luné 只参考固定日常、当日一次、到点提醒这三个功能定义，独立编写页面、存储和闹钟；没有复制参考小票 UI、示例代码或样式。原仓库：<https://github.com/nonchaiovo/timed-checklist>。

## 用法与数据

侧边栏「待办」现在显示「今日清单」。新建时可选择：

- **每天都在**：次日按浏览器记录的时区重置勾选，条目保留。
- **今天一次**：跨过当地午夜后自动从活动清单清除。
- **到点提醒**：选日期时间，或从现在起 N 分钟；选可见范围及提醒房间。到点由该房间已连接的模型生成一条短消息，保存到原聊天记录，并沿现有 SSE / Web Push 通道送达。完成的定时项次日清除；未完成的保留为逾期。已有普通待办没有 `cycle` 字段，不会被自动删除或重置。

所有条目继续保存在 `lune_workspace` 的 `todo`，版本冲突和 JSON 导出/导入沿用原路径。新增的 `data.cycle`、`timezone`、`cycle_day`、`trigger_at`（毫秒时间戳）与 `alarm_room` 均随记录导出；另有服务端 `lune_checklist_alarms` 保存独立的投递状态。导入定时项后，检查器会从活动清单重建待投递状态。浏览器本机离线可以先记清单；打开待办页或页面跨日时会按条目时区整理本机清单，但不能在关闭页面后唤醒模型。到点发消息必须连接运行中的私人服务器和可用模型，手机通知还取决于设备是否订阅 Web Push。

## 送达规则

服务进程每 15 秒检查到点项，SQLite 事务内原子认领。最多同时处理三项，每次模型调用设 45 秒上限。生成结果与聊天消息、投递状态在同一数据库事务落盘；实时连接或推送故障不会再次调用模型。模型暂时失败可在到点后 15 分钟内最多尝试三次；过窗标记「未能送达」，清单仍显示逾期。服务重启后仅重试没有持久消息且仍在窗口内的认领。用户在生成期间完成、删除或改时间，不会收到旧提醒。

提醒是用户明确设置的定时任务，和 Room 的自发闲聊频率/免打扰是两类入口。模型只看任务标题及该房间允许的资料，不自动改动清单，也不伪造用户新消息。时区用于次日重置；界面显示绝对时间戳时使用设备当地时区。服务器不运行时不会准点检查，过了短重试窗口的提醒保留逾期而不补发陈旧消息。
