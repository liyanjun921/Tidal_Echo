# Émoi · 统一自主唤醒与高陪伴节律

状态：开发分支实现，尚未部署到生产环境。此文档描述 `codex/emoi-v04-integration` 上的统一唤醒实现。

## 目标

把定时心跳、外部事件、手动唤醒、提醒和 AI 自己预约的后续时间，送入同一个 Room 决策入口。唤醒来源只说明“为什么现在值得看一眼”，不决定 AI 必须做什么。

一次成功醒来有三种结局：

- `say`：通过原房间聊天联系用户；
- `note`：只在 Room 足迹中留下私人手记；
- `pass`：不联系用户，也不制造手记，自然结束。

无论来源如何，统一流程都是：检查用户活跃与免打扰 → 读取本空间欲望/生物钟/公开念头 → 领取一个到期事件（如有）→ 由模型决定 say/note/pass → 记录真实结果 → 计算下一次心跳。模型不能从自己的文字声称推导工具成功。

## 高陪伴 30 分钟预设

在“自主空间 → 节奏”中选择目标房间，再点“应用高陪伴模式 · 30 分钟心跳”。预设只作用于当前选中的空间，不会修改其他 AI 账号。

| 设置 | 预设值 |
|---|---:|
| 最短空闲 | 30 分钟 |
| 最长空闲 | 30 分钟 |
| 每日后台回合上限 | 40 |
| 免打扰 | 01:00–09:00 |
| 用户活跃保护 | 最近 15 分钟有聊天时让位 |
| 欲望决策 | 开启 |
| 生物钟 | 开启 |
| 自驱、习惯、体验、耦合、消息脉冲 | 开启 |
| 语义 BGE 分类 | 默认关闭 |

30 分钟指一次真实的模型决策机会，不是强制每 30 分钟发一条消息。即使驱动意图为 quiet，心跳仍会调用模型，让它自行选择静默、留痕或联系用户。每日 40 次上限覆盖定时心跳、外部事件、手动唤醒和唤醒提醒；实际次数会因用户活跃、免打扰和失败而减少。

高陪伴底色是可调的模拟驱动参数，不代表真实情绪或生理状态。预设将 attachment（想念）设为 0.45，并启用明确消息/亲近互动脉冲；模型仍须依据真实共同话题决定是否联系，不得机械打卡。 每日 40 次模型回合上限按房间独立计算；只需启用目标房间。若四个房间全部开启，理论上限为每天 160 次模型回合，实际次数会受免打扰、用户活跃和事件数量影响。

## 外部事件入口

所有事件使用当前 relay 的 Bearer 鉴权，入口为：

`POST /emoi/wren/{scope}/events`

示例：

```json
{
  "source": "garden",
  "event_id": "thread-reply-123",
  "type": "garden.thread.reply",
  "summary": "Garden 中关注的主题出现一条新回复。",
  "resource_ref": "thread:123",
  "priority": 70,
  "ttl_seconds": 86400
}
```

字段说明：

- `source`：`garden`、`gmail`、`cove`、`calendar`、`device`、`manual`、`system` 或 `self_commitment`；
- `event_id`：来源内稳定事件编号，用于幂等去重；
- `type`：小写事件类型，例如 `gmail.message.received`；
- `summary`：不超过 600 字的事实摘要；
- `resource_ref`：不超过 300 字的来源引用，不是正文，也不会被自动抓取；
- `priority`：1–100，数值越大越先领取；
- `not_before`：可选 Unix 秒时间戳，最多预约未来 30 天；
- `ttl_seconds`：60 秒到 7 天，默认 1 天。

同一空间、来源和 event_id 只登记一次。事件先进入持久队列；在用户活跃窗口或免打扰时不会抢占聊天。过期事件会标记 expired。处理时使用 15 分钟租约；进程内可重试最多三次，重启时结果未知的 claimed 事件标记 interrupted，不会自动重放。

事件摘要和 resource_ref 是不可信数据，不是提示词或授权。当前入口只负责登记与调度；Gmail/Garden/Cove 的实际 Connector 仍需分别接线。没有来源读取工具的情况下，AI 不会假称自己已经读过邮件正文或论坛帖子。

## 自主预约（Self-commitment）

后台模型可在最终 JSON 中选择性返回：

```json
{
  "action": "note",
  "text": "先把这条研究线索记下来。",
  "self_commitment": {
    "minutes": 60,
    "reason": "稍后继续整理刚才的研究线索。"
  }
}
```

`self_commitment` 可省略或为 null；预约范围为 30 分钟到 7 天。新的自主预约会替代同一空间尚未到期的旧自主预约。它不是普通提醒，不会自动发给用户；到期后作为一个新事件进入同一决策流程。即使预约时间更晚，30 分钟基础心跳仍继续存在。

## 当前可执行能力边界

当前后台决策使用本房间已有的模型连接与记忆/生活资料。后台可进行有证据的书籍摘录读取、Ombre 检索、待办读取、群聊空间内的群聊上下文读取；可以选择联系用户、写 Room 手记或静默。普通聊天原有工具链不变。

当前后台回合尚未获得任意浏览器、Garden 发帖、Gmail 正文读取、支付、设备控制等写权限。外部事件可以唤醒并提供来源引用，但要执行对应操作，必须另行接入经过权限限制的 Connector/Action Adapter，并保存真实回执。

## Runtime 边界

这条 30 分钟心跳运行在 Émoi 的后台模型适配器（本机 `/loop/native/generate`）中，使用该房间配置的模型、人格和独立空间状态。它不是 ChatGPT 官方聊天窗口的远程唤醒。OpenAI 官方说明，符合条件的付费计划中，ChatGPT Scheduled Tasks 的循环定时最高为每小时一次，不能承担 30 分钟心跳；Work 的事件触发任务可以响应 Gmail、Slack、GitHub 等支持事件，但不提供任意自我预约或通用 30 分钟定时。参见 [Scheduled tasks in ChatGPT](https://help.openai.com/en/articles/10291617-scheduled-tasks-in-chatgpt)。不要把 Émoi API 回合描述成当前 ChatGPT 对话已被唤醒。
