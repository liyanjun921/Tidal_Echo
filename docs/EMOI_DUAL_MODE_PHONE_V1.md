# Émoi · 双界面与小手机模式（第一阶段）

设计依据：用户提供的 Émoi 原创艺术方向、iOS 液态玻璃与 iMessage 使用感；对用户 GitHub `liyanjun921/ai-virtual-phone` 中 Float 桌面操作逻辑的概念级研究。**只参考桌面、APP 入口和部件布局的交互类型，Émoi UI、SVG、代码均为独立实现**。Float 的实现代码、图标资产、字体及商用素材未复制到 Émoi。

## 两个模式

- **小手机模式（本次实现）**：手机浏览器原生屏宽，桌面浏览器居中显示虚拟手机外框。默认展示首页（不再从空白 GPT 聊天框开始），可打开玻璃时钟/日记组件、信息、通讯录、记忆、共读、日记、日历、影院、Room、清单、更多和设置。
- **艺术模式（保留且尚未重做）**：原 Émoi Archive Glass 网页外壳继续存在；这是未来进一步开发的独立风格，当前不宣称已匹配用户喜欢的视觉稿。
- 模式独立存储在 `localStorage.emoi-ui-mode-v1`，切换不删除旧消息、OB、Room 或后端数据；两种模式最终使用相同的真实联系人、模型和权限。

## 小手机操作方式

- 首页点击图标进入应用，透明玻璃 Dock 是常用入口；壁纸按钮操作小手机首页的独立壁纸。
- **信息 / 通讯录从零开始，不自动出现 GPT、Claude、群聊联系人。** 首次进入空状态可创建本机联系人草稿（名字、简介），可以编辑、删除。联系人草稿只在当前浏览器 `emoi-ui-contacts-v1` 保存。
- 群聊由用户自己创建草稿、选择现有联系人；`emoi-ui-groups-v1` 存储本机草稿。
- **联系人及群聊草稿尚不是真正的 AI 对话，也不关联或自动创建 OB、Desire 空间**。用户可以在“信息 → 打开原有会话（兼容入口）”找到旧版 GPT/Claude/Group，会继续使用现有真实聊天。这项隔离限制必须在 UI 和发布说明中明确，避免因视觉相似误认新联系人可以独立收发或保存记忆。
- 记忆等旧应用接原有 `window.EmoiApp.openPage`，Room 接已有 `#openWrenRoom`。旧应用内部的固定房间选择仍然存在，须在真正的多 AI 数据模型阶段迁移；**不得把隐藏固定房间标签当成已完成身份隔离。**
- “设置 → 界面模式”可切换；艺术模式从“更多 → 切换小手机模式”返回。全局玻璃、手机壁纸仍复用现有系统。

## 验收与部署边界

自动化真实 Chrome 截图检查：390px 手机首页、空消息、添加联系人、联系人详情、自建群聊、进入记忆、切换到艺术模式、1440px 桌面手机外框与设置页。测试使用本机临时 HTTP，不接入私人服务，不含真实密钥。

本 PR 只在 `design/emoi-dual-mode-phone-v1` 分支交付，**不会自动部署到腾讯云，也不会合并尚未获用户视觉确认的设计**。真机测试应补充 iPhone Safari/PWA 原生状态栏和键盘弹出体验。

下一阶段单独实现：
1. 联系人永久 ID 与模型连接脱钩；无预置 GPT/Claude/群聊
2. 真实会话 `conversation_id` → `contact_id` 多对一 / 群成员权限
3. OB 隔离租户/共享授权以及每个联系人 Desire 空间的 ACL
4. 每个旧应用页面改造成与小手机一致的 iOS 交互，避免固定角色名泄露到新 UI
5. 艺术模式完全独立的导航和视觉
